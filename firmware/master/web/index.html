      Pop-ups

      A pop-up takes over the display for its show time, then the base mode comes back. High interrupts anything; normal only interrupts the base mode (ignored while another pop-up is up); low only shows when the base mode has been up for a minute. Every = on a timer, aligned to the clock (15 = :00 :15 :30 :45), within the time window and days. Events (print done, messages, scheduled messages, a BART train N minutes away) pop up when they happen.

      Schedule a message

      A pop-up: it shows for its time, then the base mode comes back. Example: every 60 minutes, 8 more times, 300 seconds each. "Keep showing" instead makes it the text-mode message.

        Units

        # Status Firmware Supply Magnet Misses Boots I2C errors

        Hover a column heading or a value for a short explanation. Diagnostics (supply, magnet, misses, boots) need unit firmware 2.0.0. Calibrate opens the console.

        Column key
        #
        I2C address, the unit's place in the display counting from the left, starting at 0.
        Status
        Ready, moving, homing (looking for the magnet, or applying the offset), or ERROR: magnet not found.
        Firmware
        Unit firmware version. "no offset!" means no calibration offset is stored yet: run Calibrate.
        Supply
        4.98 V (4.62) = voltage now, read while the motor is idle, and in parentheses the lowest voltage seen while the motor was running. A big gap means the supply or wiring sags under load; the unit is flagged when the lowest value falls below 4.5 V. The motor must have run since boot (or since the stats were cleared) for the lowest value to exist.
        Magnet
        38 · +1 (3) = three numbers. 38 is how many times the drum's magnet has passed the hall sensor (about once per turn of the drum; each pass re-checks the unit's position). +1 is the last correction, in motor steps (2048 steps = one turn): how far off the unit's counted position was when the magnet passed; + means the drum was behind, - ahead. (3) is the largest correction ever seen (ignoring sign). Small values (a few steps) are normal; flagged when the largest passes 10.
        Misses
        Times the magnet did not show up where expected (or a homing turn failed): a slipping drum, a weak magnet or a flaky hall sensor. Should stay 0.
        Boots
        How many times the unit has restarted. A rising number means power dips or crashes.
        I2C errors
        Failed reads or writes between this controller and the unit since the controller booted: wiring, noise, or a hung unit.

        Power and heat
        
        
        
        
        
          
        
            
        
          
        
            
        
          
        
            
        
        
        
        
          
          
        • CPU speed: 160 or 80 MHz runs cooler and the display doesn't need the speed. Web pages load a little slower.
          • 
          
        • WiFi sleep: the radio naps between router beacons. Light keeps flappy.local and pings working and adds
            ~100 ms per request. Deep saves more but a mesh router may not deliver the multicast that flappy.local needs, so the
            name can stop resolving (the IP address keeps working).
          • 
          
        • Transmit power: Automatic turns the radio down while the signal is strong (next to a router) and back up when it
            gets weak (next to a far mesh node), so moving the display needs no changes. Low is fixed.
          • 
          
        • Quiet hours (Display tab) add WiFi sleep and 80 MHz on top of these.

        Siri, Home Assistant and scripts
        
        
        Anything on the home network can put text on the display:
        
        
        curl -H 'Content-Type: application/json' \
  -d '{"text":"WASHER DONE","seconds":60}' http://192.168.0.111/api/message
        
        
        seconds = show for a while, then back to the current mode (leave it out to keep showing it).
          Step-by-step setup for a Siri Shortcut ("Hey Siri, Flappy") and Home Assistant
          (rest_command + automations) is in docs/integrations.md.
